# KosmoHackathon Submit

Управляй уже существующим сабмиттером через корневой `submit.sh`. Не дублируй Selenium-логику в skill.

## Область действия

Работай только из корня репозитория, в котором одновременно существуют:

- `submit.sh`
- `api/config.yaml`
- `api/submit.py`

Если этих файлов нет, остановись: этот skill не предназначен для другого проекта.

Не читай и не показывай содержимое `api/credentials.env`, профиля Chrome или cookies. Для диагностики используй только сообщения команды и логи.

## Выбор файла

Используй путь, явно указанный пользователем. Если путь не указан, используй `artifacts/submission.csv`, только если файл существует. Иначе попроси пользователя назвать CSV-файл.

Перед запуском проверь, что выбранный путь указывает на обычный файл. Встроенная в submitter валидация проверит CSV, колонки, строки и соответствие тестовому датасету.

## Dry-run

Если пользователь просит проверить форму, загрузку файла или выполнить пробный запуск, выполни:

```bash
./submit.sh <file> --dry-run --json
```

Dry-run выбирает файл в форме, но не нажимает кнопку отправки. Браузер после него остаётся открытым. Не сообщай, что решение отправлено, и не ожидай метрику.

Перед следующим запуском предупреди пользователя закрыть оставленное dry-run окно, если профиль Chrome заблокирован этим окном.

## Реальная отправка

Реальная отправка изменяет состояние внешнего сервера. Запускай её только по явной просьбе пользователя отправить конкретный файл. Одна такая просьба разрешает одну попытку:

```bash
./submit.sh <file> --json
```

Не повторяй неудачную или зависшую отправку автоматически: сначала установи, произошла ли отправка на сервере, и сообщи пользователю.

Не добавляй `--allow-duplicate`, если пользователь явно не попросил повторно отправить тот же файл. Для разрешённой повторной отправки выполни:

```bash
./submit.sh <file> --allow-duplicate --json
```

После успеха прочитай JSON команды и сообщи:

- локальный статус;
- дату и статус верхней строки таблицы платформы;
- значение `score` как метрику решения.

Не вычисляй метрику самостоятельно и не подменяй её локальной оценкой.

## Авторизация и сессия

По умолчанию используй сохранённую сессию отдельного постоянного Chrome-профиля сабмиттера.

Не применяй `--reset-session` без явной просьбы пользователя сбросить вход или убедительных логов о повреждённой сессии: флаг удаляет cookies и web storage платформы.

Если требуется ручной вход и пользователь может взаимодействовать с открытым браузером, запусти по его просьбе:

```bash
./submit.sh <file> --dry-run --manual-login --json
```

Не сочетай ручную авторизацию с headless-режимом.

## Диагностика

При ошибке сначала изучи:

- `artifacts/submissions/logs/submitter.log`
- `artifacts/submissions/logs/chromedriver.log`

Разделяй ошибки валидации CSV, авторизации, Selenium/Chrome, нажатия кнопки и ожидания результата. Не включай секреты в ответ или команды.

Не делай скриншоты без отдельной просьбы пользователя.
